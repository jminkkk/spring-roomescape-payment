# Phase 5: 커버리지 점검 + 보강 + 전체 그린

**시작 전에 `00_overview.md`를 먼저 읽을 것.** 특히 "개발 방식: TDD"와 "전체 완료 기준".

## 선행 조건

Phase 1~4 완료 — Kafka 기반 복구 플로우가 동작하고, 기존 Outbox 코드와 Outbox 기준 레거시 테스트는
삭제된 상태.

## 목표

TDD로 진행했으므로 테스트는 Phase 2·3에서 **이미 먼저** 나와 있다. 이 Phase는 테스트를 처음부터 쓰는
단계가 아니라 **점검하는 단계**다:

1. 완료 기준의 시나리오가 전부 테스트로 덮였는지 **매핑**한다.
2. 빈칸만 **테스트 먼저** 작성해 보강한다.
3. Phase 2·3 어디에서도 검증되지 않는 **이음새**(진짜 end-to-end)를 검증한다.
4. 간헐 실패가 없는지, 전체 스위트가 그린인지 확인한다.

## 할 일

### 1. 시나리오 ↔ 테스트 매핑표 작성

아래 표를 이 파일 하단(또는 Phase 6 메모)에 채운다. **"어느 테스트 클래스의 어느 메서드가 이 시나리오를
증명하는가"**를 적는다.

| 시나리오 | 출처 | 증명하는 테스트 (클래스#메서드) |
|---|---|---|
| 정상 복구: 발행된 메시지가 처리되어 `COMPLETED` | Phase 3 | |
| 멱등성: 이미 `COMPLETED`면 저장하지 않음 | Phase 3 | |
| 재시도 3회 후 DLT 도달 | Phase 3 | |
| 재시도 불가(역직렬화 실패) → 즉시 DLT | Phase 3 | |
| 재시도 불가(Payment 미존재) → 즉시 DLT | Phase 3 | |
| **DLQ 재투입 → `COMPLETED`** | Phase 3 | |
| publish 실패 → CRITICAL 로그 | Phase 2 | |
| 키·payload·타입 헤더 형식 | Phase 2 | |
| tx3 롤백 → 메시지 발행 | Phase 2 | |
| **end-to-end: 예약 생성 → tx3 롤백 → 발행 → 소비 → `COMPLETED`** | **Phase 5 고유** | |

### 2. 빈칸 보강 — 보강분은 TDD로

- 빈칸인 시나리오는 **테스트를 먼저 쓴다.**
- 🔴 **새로 쓴 테스트가 처음부터 통과하면, 그 테스트가 정말 무언가를 검증하는지 확인한다.** 이미 구현된
  기능을 보강하는 테스트는 RED를 거치지 않는다. 해당 프로덕션 코드를 **잠시 깨뜨려서**(예: 멱등 체크 주석 처리)
  테스트가 실패하는 것을 본 뒤 되돌린다. 안 깨지는 테스트는 아무것도 증명하지 않는다.

### 3. end-to-end 테스트 (Phase 5 고유)

Phase 2는 "발행까지", Phase 3은 "소비부터"를 검증한다. **둘을 잇는 이음새는 여기서만 검증된다.**

- `@KafkaIntegrationTest`로, 예약 생성 플로우(`ReservationApplicationService.createReservation` 또는 API)를 호출한다.
- PG 호출은 성공하고, `PaymentService.completePayment`의 저장이 **처음 한 번만** 실패하도록 만든다
  (tx3 롤백 유도). 이후 Consumer의 처리는 성공해야 한다.
- 최종적으로 해당 Payment가 `COMPLETED`가 되는 것을 Awaitility로 확인한다.
- 이 테스트가 Phase 4에서 삭제한 `createReservation_PaymentSuccess_DBFail_OutboxCreated`의 대체물이다.

### 4. 간헐 실패 점검

- Kafka 통합 테스트를 **최소 5회 반복 실행**해서 전부 통과하는지 본다.
- 한 번이라도 실패하면 고정 대기(`Thread.sleep`)나 `auto.offset.reset`, Awaitility 타임아웃을 먼저 의심한다.

### 5. 전체 그린

- `./gradlew test`가 이번 전환과 무관한 기존 실패 없이 통과한다.
- 전환 중 새로 발견한 **기존** 결함은 고치지 말고 목록으로만 남겨 Phase 6 다음 트랙 메모로 넘긴다.

## 완료 기준

- 매핑표에 **빈칸이 없다.**
- 보강한 테스트는 모두 "코드를 깨뜨리면 실패한다"를 확인했다.
- end-to-end 테스트가 통과한다.
- Kafka 통합 테스트가 5회 반복 실행에서 모두 통과한다.
- `./gradlew test`가 그린이다 (무관한 기존 실패는 목록으로 분리).

## 이번 Phase에서 하지 않는 것

- Phase 2·3에서 이미 있는 테스트를 다시 쓰는 것 — 매핑만 한다
- 성능/부하 테스트 (필요하면 `perf-test/k6` 패턴 참고해 별도 트랙으로)
- 운영 배포 전 체크리스트 작성 (이번 전환은 로컬 범위, 00_overview.md 참고)
- `payment.status=IN_PROGRESS` 정산 스윕 테스트 — 구현 자체가 범위 밖 (다음 트랙)
- 발견한 기존 결함의 수정
